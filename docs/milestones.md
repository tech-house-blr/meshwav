# Milestones

Each milestone ends with working, tested, measured output. No placeholders presented as done.

- M0: Architecture docs (this commit). Exit: approved by Boss.
- M1 (done): Spike and protocol. Cargo workspace; `audio-protocol` with serialization, AEAD, replay window, test vectors + tests; Opus/FLAC/PCM round-trip tests; UDP + TCP echo and RTT/loss measurement over real Tailscale (Pi to phone/PC). Exit: numbers recorded in docs/measurements.md.
- M2: Desktop prototype. `audio-capture` (PipeWire on the Pi/Linux, WASAPI on Windows), Opus encode, send to a configured tailnet IP; verify with a Rust test receiver that plays audio. Exit: audible and glitch-free for 30 min.
- M3: Android prototype. Kotlin receiver: UDP, Opus decode, AudioTrack; manual IP; foreground service. Exit: real end-to-end playback on a phone; latency measured with a loopback click test.
- M4: Integration. Noise handshake, pairing, control channel, jitter buffer + PLC, reconnection, stats/diagnostics, bitrate/frame config, then lossless profile (PCM, FLAC) with format negotiation and bit-perfect detection. Exit: targets in architecture.md measured; loss-injection tests pass.
- M4 progress: M4a (jitter buffer, concealment, reconnect, stats) merged. M4b part 1 (Noise handshake, pairing, pinned keys, session keys) done on its branch. M4b part 2a: runtime bitrate and frame-size control over sealed control packets. Still open in M4: lossless profile (with format negotiation), measured latency targets.
- Where it stands (v0.5.0): M2 to M4 are done except the open items above (latency target met only with the experimental native Android output, on one phone; FLAC and bit-perfect detection not built). Done on the way: runtime codec and frame-size control, lossless PCM, receiver selection, systemd user service, config file and log levels, deb, rpm and Arch packaging, a Linux receiver and window, one `meshwav` program, phone as a source, code-only pairing, the sender-stamped end-to-end latency readout, an optional native AAudio output on Android, and fixes from a security review (pairing links, per-source handshake limits, a key fingerprint check for code-only pairing). Windows now works as sender (WASAPI loopback, output turned down while a receiver plays) and receiver (WASAPI), with a window, a tray icon, a login startup entry and a single portable `meshwav.exe`. Not done: Windows latency numbers, following a change of the default output on Windows, code-signing the Windows build, a hosted apt/dnf repo, peer discovery beyond pairing.
- M5: Productization. Compose UI polish, discovery via Tailscale peer list, systemd/Windows services, config + logging, install docs, release builds.
- Later (not before M4 stable): per-app capture, adaptive bitrate, remote volume, macOS. (Multi-receiver selection and the phone as a source have shipped.)
